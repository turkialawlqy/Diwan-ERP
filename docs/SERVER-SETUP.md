# دليل إعداد خادم «الديوان» من الصفر

دليل كامل لتجهيز خادم إنتاجي جديد على DigitalOcean: من إنشاء الخادم حتى تسجيل أول منشأة. كل خطوة فيها ما تضغط عليه أو تكتبه بالضبط.

> **قبل البدء:** اقرأ الدليل مرة كاملة. احجز ساعة تقريباً، معظمها انتظار لانتشار الـ DNS وتثبيت الحزم.

## 1. ما تحتاجه قبل البدء

| العنصر | ملاحظة |
|---|---|
| حساب DigitalOcean | بوسيلة دفع مفعّلة. |
| نطاق (Domain) مسجّل ومفعّل | مثل `vatrix.app`. يجب أن تكون حالته **Active** عند المسجّل، وأن تكون قد أكدت رسالة التحقق التي يرسلها المسجّل إلى بريدك بعد الشراء. |
| الوصول إلى مستودع GitHub | بصلاحية إدارة المستودع (Admin)، لإضافة مفتاح النشر. |
| بريد لإرسال رسائل النظام | خدمة SMTP (انظر القسم 5). |
| جهازك | ويندوز بـ PowerShell، أو أي جهاز فيه `ssh`. |
| مدير كلمات مرور | لحفظ الأسرار التي يولّدها التثبيت. |

## 2. إنشاء الخادم (Droplet)

من لوحة DigitalOcean: **Create ← Droplets**.

| الإعداد | الاختيار الموصى به | السبب |
|---|---|---|
| **المنطقة (Region)** | Frankfurt (FRA1) أو Singapore (SGP1)، أيهما أقرب لعملائك | الأقرب للسعودية والخليج. |
| **النظام (Image)** | **Ubuntu 24.04 (LTS) x64** | يأتي بـ PHP 8.3 المختبر مع النظام. Ubuntu 26.04 يأتي بـ PHP 8.5، والسكربت يعمل عليه، لكن 24.04 أكثر استقراراً للإنتاج. |
| **الحجم (Size)** | **Basic ← Regular ← 2 GB RAM / 1 CPU / 50 GB** كحد أدنى، و**4 GB / 2 CPU** إن كان العملاء كثيرين | خادم 512MB يكفي للتجربة فقط: بناء الواجهة عليه يأخذ نحو 8 دقائق، ويضغط الذاكرة. |
| **التوثيق (Authentication)** | **SSH Key** | أكثر أماناً من كلمة المرور (الخطوات أدناه). |
| **النسخ الاحتياطي (Backups)** | فعّل **Weekly backups** | نسخة كاملة للخادم من DigitalOcean، إضافة إلى نسخ النظام اليومية. |
| **اسم الخادم (Hostname)** | مثل `diwan-prod` | للتمييز فقط. |

### إنشاء مفتاح SSH على ويندوز (إن لم يكن لديك)

افتح PowerShell:
```powershell
ssh-keygen -t ed25519 -C "your-email@example.com"
```
اضغط Enter لكل الأسئلة، أو ضع كلمة مرور للمفتاح إن أردت. ثم اعرض المفتاح العام وانسخه:
```powershell
type $env:USERPROFILE\.ssh\id_ed25519.pub
```
في صفحة إنشاء الخادم: **SSH Key ← New SSH Key**، والصق المفتاح.

اضغط **Create Droplet**. بعد دقيقة يظهر **عنوان IP** للخادم (ipv4)، **سجّله**، وسنسميه في هذا الدليل `IP-الخادم`.

> **انتبه:** استخدم عنوان IP خادمك من صفحة الـ Droplet، وليس أي عنوان من مواقع أخرى أو أمثلة.

## 3. ربط النطاق بـ DigitalOcean

نجعل DigitalOcean يدير الـ DNS لنطاقك. هذا لازم لإصدار شهادة SSL تشمل كل النطاقات الفرعية للمنشآت (`*.نطاقك`) وتجديدها تلقائياً.

### أ. أضف النطاق في DigitalOcean
**Networking ← Domains ← Add Domain**: اكتب نطاقك (مثل `vatrix.app`)، واختر الخادم، ثم **Add Domain**.

### ب. أضف سجلّي A
في صفحة النطاق داخل DigitalOcean أضف:

| Type | Hostname | Will direct to | TTL |
|---|---|---|---|
| A | `@` | خادمك (`IP-الخادم`) | 3600 |
| A | `*` | خادمك (`IP-الخادم`) | 3600 |

السجل الأول للنطاق الرئيسي، والثاني (`*`) لكل منشأة على `اسمها.نطاقك`.

### ج. غيّر خوادم الأسماء عند مسجّل النطاق
في لوحة المسجّل (GoDaddy أو Namecheap أو غيرهما) ابحث عن **Nameservers ← Custom**، وضع:
```
ns1.digitalocean.com
ns2.digitalocean.com
ns3.digitalocean.com
```
ثم احفظ.

### د. تحقق من الانتشار
قد يأخذ من دقائق إلى 48 ساعة، وغالباً أقل من ساعتين. من PowerShell على جهازك:
```powershell
nslookup -type=NS vatrix.app
nslookup vatrix.app
nslookup test.vatrix.app
```
النتيجة الصحيحة:
- الأمر الأول يُظهر `ns1.digitalocean.com` وأخواته.
- الأمران الآخران يُظهران `IP-الخادم`.

> إن ظهر `Non-existent domain` بعد ساعات، فالمشكلة عند المسجّل: النطاق غير مفعّل، أو خوادم الأسماء لم تُحفظ. راجعه قبل المتابعة.

**يمكنك متابعة الخطوات 4 إلى 7 أثناء الانتظار**، وإن لم ينتشر الـ DNS بعد فاتبع [التثبيت بنطاق تجربة](#التثبيت-قبل-انتشار-الـ-dns).

## 4. إنشاء رمز API لشهادة SSL

**API ← Tokens ← Generate New Token**:

| الحقل | القيمة |
|---|---|
| Name | `diwan-certbot` |
| Expiration | **No expiry**؛ وإلا توقف تجديد الشهادة عند انتهاء الرمز. |
| Scopes | **Custom Scopes** ثم اختر **domain** بصلاحيتي read و update، أو **Full Access** إن لم تتوفر الصلاحيات المخصصة. |

انسخ الرمز فوراً، فهو لا يُعرض مرة أخرى، واحفظه في مدير كلمات المرور.

## 5. تجهيز البريد (SMTP)

النظام يرسل بريداً لـ: تأكيد البريد، واستعادة كلمة المرور، وإرسال الفواتير وكشوف الحساب للعملاء، وتنبيهات النسخ الاحتياطي. بدون SMTP **لن تصل هذه الرسائل**.

الخيارات:

| الخدمة | ملاحظة |
|---|---|
| **Zoho Mail** أو **Google Workspace** | إن كان لديك بريد رسمي على نطاقك. |
| **Brevo** أو **Mailgun** أو **Amazon SES** | خدمات إرسال مخصصة، أفضل للكميات وأقل عرضة لتصنيف الرسائل كبريد مزعج. |

ستحتاج: **الخادم (host)، والمنفذ (port، غالباً 587)، واسم المستخدم، وكلمة المرور، وعنوان المرسل** (مثل `no-reply@vatrix.app`).

> أضف سجلات **SPF و DKIM** التي تعطيك إياها خدمة البريد في صفحة النطاق في DigitalOcean، حتى لا تذهب الرسائل إلى البريد المزعج.

يمكنك تخطي هذه الخطوة الآن وإضافة البريد لاحقاً (القسم 8).

## 6. الدخول إلى الخادم ونقل سكربت التثبيت

### أ. حدّث نسختك المحلية من المشروع
على جهازك، في مجلد المشروع (مثل `C:\MAMP\htdocs\alostaz`):
```powershell
cd C:\MAMP\htdocs\alostaz
git pull
```
تأكد أن الملف موجود: `deploy\ubuntu\install.sh`.

### ب. انقل السكربت إلى الخادم
```powershell
scp "C:\MAMP\htdocs\alostaz\deploy\ubuntu\install.sh" root@IP-الخادم:/root/
```

> **بديل إن لم ينجح `scp`:** افتح الملف على GitHub (الفرع المستخدم ← `deploy/ubuntu/install.sh` ← **Raw**) وانسخ محتواه. ثم على الخادم نفّذ `nano /root/install.sh`، والصق بالزر الأيمن، واحفظ بـ `Ctrl+O` ثم `Enter`، واخرج بـ `Ctrl+X`.

### ج. ادخل إلى الخادم
```powershell
ssh root@IP-الخادم
```
عند أول دخول اكتب `yes` لقبول بصمة الخادم.

## 7. تشغيل التثبيت

```bash
sudo bash /root/install.sh
```

### الأسئلة وإجاباتها

| السؤال | ماذا تكتب |
|---|---|
| النطاق الرئيسي | `vatrix.app`، بلا `https://` وبلا `www`. |
| بريد مدير المنصة | بريدك؛ هو حساب إدارة المنصة كلها. |
| مستودع الكود | اضغط **Enter** لقبول الافتراضي. |
| الفرع | اضغط **Enter**، أو اكتب فرع الإصدارات المستقرة إن وُجد. |
| DO API token | الرمز من القسم 4. لا يظهر أثناء الكتابة، وهذا طبيعي. |
| SMTP host وما بعده | بيانات القسم 5، أو اضغط Enter لتخطيها الآن. |

### مفتاح النشر (Deploy Key)
سيتوقف السكربت ويعرض سطراً يبدأ بـ `ssh-ed25519 ...`. هذا مفتاح يسمح للخادم **بقراءة** المستودع فقط:

1. انسخ السطر كاملاً.
2. في GitHub: **المستودع ← Settings ← Deploy keys ← Add deploy key**.
3. Title: `diwan-prod`. Key: الصق السطر. **اترك «Allow write access» غير مفعّل**.
4. **Add key**، ثم ارجع للخادم واضغط **Enter**.

### ما يفعله السكربت بعدها (تلقائياً)

| الخطوة | المحتوى |
|---|---|
| 1 | تحديث النظام، وذاكرة swap، والمنطقة الزمنية (الرياض)، والجدار الناري (المنافذ 22 و80 و443 فقط). |
| 2 | تثبيت Nginx وPHP وMySQL وRedis وSupervisor وCertbot. |
| 3 | إنشاء قاعدة البيانات ومستخدمها بكلمة مرور عشوائية. |
| 4 | مفتاح النشر (أعلاه). |
| 5 | سحب الكود، وتثبيت المكتبات، وبناء الواجهة. هذه أطول خطوة: دقيقتان إلى عشر دقائق حسب حجم الخادم. |
| 6 | ملف الإعدادات `.env` وأسراره. |
| 7 | جداول قاعدة البيانات وباقات الاشتراك. |
| 8 | إعداد Nginx. |
| 9 | شهادة SSL للنطاق وكل نطاقاته الفرعية (تتجدد تلقائياً). |
| 10 | العمليات الخلفية: الإرسال لهيئة الزكاة، والنسخ الاحتياطي اليومي، والتنبيهات، والقيود الدورية. |
| 11 | **إنشاء مدير المنصة**: يطلب كلمة مرور (10 أحرف على الأقل، ولا تظهر أثناء الكتابة)، ثم الفحص النهائي. |

تنتهي العملية برسالة **«تم تثبيت «الديوان»»** ومعها الروابط.

> **إن توقف السكربت في أي خطوة:** اقرأ آخر الرسائل وراجع [حل المشكلات](#14-حل-المشكلات-الشائعة)، ثم أعد تشغيله. إعادة التشغيل آمنة: يتذكر إجاباتك في `/root/.diwan-install.conf`، ولا يعيد إنشاء قاعدة البيانات، ولا يعيد بناء الواجهة إن لم تتغير.

### التثبيت قبل انتشار الـ DNS

إن لم ينتشر نطاقك بعد، يمكنك التثبيت والتجربة الآن بنطاق تجربة مجاني يعمل فوراً مع النطاقات الفرعية (بلا SSL):
```bash
DIWAN_DOMAIN=IP-الخادم.sslip.io bash /root/install.sh
```
مثال: `DIWAN_DOMAIN=167.71.196.39.sslip.io`. ثم افتح `http://167.71.196.39.sslip.io/register`.

وبعد انتشار نطاقك الحقيقي، انتقل إليه بأمر واحد (يصدر الشهادة ويحوّل كل شيء إلى https، وتبقى المنشآت بأسمائها):
```bash
DIWAN_DOMAIN=vatrix.app bash /var/www/diwan/deploy/ubuntu/install.sh
```

## 8. بعد التثبيت مباشرة

### أ. احفظ الأسرار ثم احذف ملفها
```bash
cat /root/diwan-secrets.txt
```
انسخ القيم الثلاث (`APP_KEY` و`DB_PASSWORD` و`BACKUP_PASSWORD`) إلى مدير كلمات المرور، ثم:
```bash
rm /root/diwan-secrets.txt
```

> **`APP_KEY` هو أهم سر:** يشفّر مفاتيح أجهزة الفوترة الإلكترونية وأسرار الربط. إن ضاع لا يمكن فك تشفيرها، وتحتاج إعادة ربط الأجهزة. **لا تغيّره أبداً بعد التشغيل.**
> و`BACKUP_PASSWORD` يلزم لفك النسخ الاحتياطية؛ بدونه لا قيمة للنسخ.

### ب. أضف البريد (إن تخطيته أثناء التثبيت)
```bash
nano /var/www/diwan/.env
```
عدّل هذه الأسطر:
```dotenv
MAIL_MAILER=smtp
MAIL_HOST=smtp.example.com
MAIL_PORT=587
MAIL_USERNAME=no-reply@vatrix.app
MAIL_PASSWORD='كلمة-مرور-البريد'
MAIL_FROM_ADDRESS=no-reply@vatrix.app
BACKUP_NOTIFY_EMAIL=you@example.com
```
احفظ، ثم طبّق التغيير:
```bash
cd /var/www/diwan && sudo -u www-data php artisan optimize && supervisorctl restart 'diwan:*'
```

### ج. تأمين الدخول إلى الخادم (موصى به)
بعد التأكد أن دخولك بمفتاح SSH يعمل، أوقف الدخول بكلمة المرور:
```bash
sed -i 's/^#\?PasswordAuthentication .*/PasswordAuthentication no/' /etc/ssh/sshd_config
systemctl restart ssh
```

## 9. النسخ الاحتياطي خارج الخادم

النظام يأخذ نسخة مشفّرة من قاعدة البيانات يومياً على الخادم نفسه. للإنتاج **يجب** أن تُرفع نسخة أيضاً خارج الخادم، حتى لا تضيع البيانات إن تعطل الخادم.

**باستخدام DigitalOcean Spaces:**
1. **Spaces Object Storage ← Create Bucket**: اختر نفس المنطقة، واسماً مثل `diwan-backups`، و**Restrict File Listing**.
2. **API ← Spaces Keys ← Generate New Key**: انسخ Key وSecret.
3. أضف إلى `/var/www/diwan/.env` (مثال لمنطقة fra1):
   ```dotenv
   BACKUP_OFFSITE_DISK=offsite
   BACKUP_S3_KEY=المفتاح
   BACKUP_S3_SECRET='السر'
   BACKUP_S3_REGION=fra1
   BACKUP_S3_BUCKET=diwan-backups
   BACKUP_S3_ENDPOINT=https://fra1.digitaloceanspaces.com
   ```
4. طبّق وجرّب نسخة فورية:
   ```bash
   cd /var/www/diwan && sudo -u www-data php artisan optimize
   sudo -u www-data php artisan erp:backup
   sudo -u www-data php artisan erp:backup --verify
   ```
   الأمر الأخير يستعيد آخر نسخة في قاعدة مؤقتة للتأكد أنها سليمة.

## 10. الفحص النهائي قبل التشغيل الفعلي

```bash
cd /var/www/diwan && sudo -u www-data php artisan erp:preflight
```
يجب ألا يظهر أي سطر يبدأ بـ **«خطأ»**. الأخطاء المعتادة وحلها:

| الرسالة | الحل |
|---|---|
| HTTPS غير مفروض | الشهادة لم تصدر: تأكد من انتشار الـ DNS ثم أعد تشغيل السكربت. |
| MAIL_MAILER لا يرسل بريداً | أضف SMTP (القسم 8-ب). |
| BACKUP_PASSWORD غير مضبوط | لا يحدث مع السكربت، إلا إن عُدّل `.env` يدوياً. |
| لا توجد نسخة خارج الخادم (تنبيه) | القسم 9. |
| فحص backup: no successful backup (تنبيه) | يزول بعد أول نسخة: `php artisan erp:backup`. |

وتحقق من صفحة الصحة في المتصفح:
`https://vatrix.app/health` يجب أن تُظهر `"ok":true` (ورمز الاستجابة 200).

## 11. أول استخدام: مدير المنصة والمنشآت

### مدير المنصة
1. افتح `https://vatrix.app/login` وادخل بالبريد وكلمة المرور التي أنشأتها في التثبيت.
2. سيُطلب منك **تفعيل التحقق الثنائي**: اتبع الخطوات في الصفحة (Google Authenticator أو Microsoft Authenticator أو Authy)، و**احفظ رموز الاسترداد**.
3. من لوحة المنصة تدير المنشآت والاشتراكات والباقات.

### تسجيل منشأة
1. افتح `https://vatrix.app/register`.
2. أدخل اسم المنشأة، والنطاق الفرعي (مثل `alostaz`)، والدولة، والعملة، وبيانات المدير.
3. تعمل المنشأة على `https://alostaz.vatrix.app`.

### إعدادات المنشأة الأولى (داخلها)
1. **الإعدادات العامة:** الشعار، والرقم الضريبي، والسجل التجاري.
2. **الفروع:** دولة كل فرع وعملته ورقمه الضريبي.
3. **الفوترة الإلكترونية** (للسعودية): بيانات البائع والعنوان الوطني، ثم ربط الجهاز برمز OTP من بوابة «فاتورة».
4. **المستخدمون والأدوار.**
5. **البيانات الافتتاحية:** العملاء والموردون والأصناف والأرصدة، من شاشة نقل البيانات أو أزرار الاستيراد من Excel.

## 12. التحديثات

عند صدور تحديث (تعديلات جديدة على الفرع)، على الخادم:
```bash
sudo bash /var/www/diwan/deploy/ubuntu/update.sh
```
التحديث **لا يوقف النظام**: المستخدمون يكملون عملهم طوال التحديث. يقوم السكربت بالتالي:
1. يجهّز الإصدار الجديد في مجلد مستقل بجانب الإصدار العامل: يسحب الكود، ويعيد تثبيت المكتبات وبناء الواجهة **فقط إن تغيّرت**، بأولوية منخفضة كي لا يبطئ الموقع.
2. إن وُجدت ترحيلات لقاعدة البيانات: يأخذ نسخة احتياطية ثم يطبّقها. إن فشلت النسخة يُلغى التحديث ويبقى النظام كما هو.
3. يحوّل النظام إلى الإصدار الجديد في لحظة واحدة: الطلبات الجارية تكتمل على الإصدار القديم، والعمليات الخلفية تُنهي مهمتها الحالية ثم تنتقل.
4. يتحقق من أن النظام يستجيب (`/up`). إن لم يستجب **يرجع تلقائياً** للإصدار السابق.
5. يحتفظ بآخر 3 إصدارات ويحذف الأقدم.

إن فشل أي خطوة قبل التحويل لا يتغير شيء على المستخدمين.

**الرجوع للإصدار السابق يدوياً** (لحظي، ولا يغيّر قاعدة البيانات):
```bash
sudo bash /var/www/diwan/deploy/ubuntu/update.sh --rollback
```

**أول مرة على خادم ثُبّت قبل هذه الميزة:** السكربت القديم الموجود على الخادم يوقف النظام. شغّل النسخة الجديدة مباشرة من المستودع:
```bash
sudo -u www-data git -C /var/www/diwan fetch -q origin
sudo -u www-data git -C /var/www/diwan show '@{u}:deploy/ubuntu/update.sh' > /root/diwan-update.sh
sudo bash /root/diwan-update.sh
```
ينقل التثبيت مرة واحدة إلى نظام الإصدارات، ثم يحدّث دون توقف. بعدها استخدم الأمر المعتاد.

> ترحيلات قاعدة البيانات تُكتب بحيث يعمل الإصدار السابق معها، لأن الإصدارين يعملان معاً لثوانٍ أثناء التحويل.

## 14. حل المشكلات الشائعة

| العَرَض | السبب والحل |
|---|---|
| `NXDOMAIN` عند إصدار الشهادة | النطاق لم يُربط بخوادم DigitalOcean بعد، أو غير مفعّل عند المسجّل. تحقق بـ `nslookup -type=NS نطاقك`، وانتظر الانتشار، ثم أعد تشغيل السكربت. التثبيت يكمل على http ولا يتوقف. |
| `JavaScript heap out of memory` أثناء البناء | ذاكرة الخادم صغيرة جداً. تأكد أن الـ swap مفعّل بالأمر `free -h` (يجب أن يظهر Swap: 2.0Gi)، أو كبّر الخادم. |
| `lock file does not contain a compatible set of packages` و `php version 8.5` | النظام يأتي بـ PHP 8.5. السكربت الحديث يتعامل مع ذلك تلقائياً؛ حدّث نسخة السكربت. والأفضل استخدام Ubuntu 24.04. |
| `detected dubious ownership in repository` | أمر git شُغّل بصلاحية root على مجلد يملكه www-data. شغّل أوامر git هكذا: `sudo -u www-data git -C /var/www/diwan ...` |
| الموقع يعرض **404 NOT FOUND** | العنوان المفتوح ليس هو النطاق المضبوط في النظام. تحقق بـ `grep APP_DOMAIN /var/www/diwan/.env`، ثم أعد تشغيل السكربت بـ `DIWAN_DOMAIN=النطاق-الصحيح`. |
| يظهر موقع آخر غير «الديوان» | النطاق (أو نطاق التجربة) يشير إلى عنوان IP غير خادمك. استخدم عنوان الخادم من صفحة الـ Droplet. |
| `Database file ... database.sqlite does not exist` | النظام لا يقرأ `.env`. أصلحه بـ `chown www-data:www-data /var/www/diwan/.env && chmod 640 /var/www/diwan/.env`، ثم `sudo -u www-data php artisan optimize:clear && sudo -u www-data php artisan optimize`. |
| خطأ 500 بعد تعديل `.env` | الإعدادات المخزنة قديمة: `cd /var/www/diwan && sudo -u www-data php artisan optimize`. |
| الفواتير «بانتظار الإرسال» للهيئة ولا تُرسل | العمليات الخلفية متوقفة: `supervisorctl status`، ثم `supervisorctl restart 'diwan:*'`. |
| لا تصل رسائل البريد | تحقق من إعدادات SMTP في `.env` ومن سجل النظام، وتأكد من سجلات SPF وDKIM. |
| مستخدم عالق في صفحة «تأكيد البريد» ولم يصله الرابط | إن كان `MAIL_MAILER=log` فالرسالة تُكتب في السجل ولا تُرسل: اضبط SMTP (القسم 8)، وفي الأثناء فعّل الحساب يدوياً بالأمر `sudo -u www-data php artisan erp:verify-user EMAIL`. |
| الموقع بطيء جداً | راقب الذاكرة بـ `free -h` والمعالج بـ `top`. غالباً يحتاج الخادم ترقية الحجم من لوحة DigitalOcean (Resize). |

إن لم تجد الحل، اجمع هذه المعلومات وأرسلها:
```bash
supervisorctl status
systemctl status nginx mysql redis-server --no-pager | grep -E "●|Active"
tail -n 50 /var/www/diwan/storage/logs/laravel-$(date +%F).log
```

## 15. مرجع سريع للأوامر

```bash
# الانتقال إلى مجلد النظام
cd /var/www/diwan

# أي أمر artisan يُشغَّل بصلاحية www-data
sudo -u www-data php artisan <الأمر>

# تحديث النظام
sudo bash /var/www/diwan/deploy/ubuntu/update.sh

# إعادة تشغيل العمليات الخلفية
supervisorctl restart 'diwan:*'

# تطبيق تعديل في .env
sudo -u www-data php artisan optimize

# وضع الصيانة وإلغاؤه
sudo -u www-data php artisan down
sudo -u www-data php artisan up

# نسخة احتياطية فورية والتحقق منها
sudo -u www-data php artisan erp:backup
sudo -u www-data php artisan erp:backup --verify

# الفحص الشامل
sudo -u www-data php artisan erp:preflight

# إعادة تشغيل الخدمات
systemctl restart nginx php*-fpm mysql redis-server
```
